Backfill for bodies stored truncated (--refetch-truncated).

Profile feeds send long posts and comments shortened: the item has body_truncated: true, a cut body doc and a body_text_summary. The thread page (/rs/post/{thread_id}, what “show more” opens) renders the root and every reply in full, so one GET per thread completes all of its stored rows. Rows stored before 1.26.0 have body_state = 'unknown' and are checked the same way.

completed_body
Decide what to store for a row given its full thread-page item: Some(text) when the full body differs from the stored one, None when it already matches. Whitespace-only differences (old single-newline paragraph joins) count as a change too, so paragraph breaks are restored.
pending_bodies
Rows whose body is not known to be complete, optionally only for nicks (case-insensitive). Ordered by thread so each thread is fetched once.
refetch_truncated
Fetch the thread page of every pending row (sequentially, pausing THREAD_FETCH_PAUSE_MS between threads) and store the full bodies.
