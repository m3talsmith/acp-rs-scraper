ATTACHMENTS_SCHEMA
attachments table: downloaded media per post, unique per (post_id, url).
BOOKMARKS_SCHEMA
bookmarks table (2.1.0). One row per bookmarked post:
MENTIONS_SCHEMA
mentions table: which posts mention which nick, and how.
POSTS_ADD_BODY_STATE
Run when posts lacks body_state (databases before 1.26.0). Values: full (complete body), truncated (only the feed’s shortened preview was available) and unknown (stored before 1.26.0, could be either; --refetch-truncated checks these against their thread page).
POSTS_ADD_IN_REPLY_TO
Run after POSTS_SCHEMA when posts lacks in_reply_to_id: add the column and point existing replies at their thread root (the best known parent).
POSTS_MIGRATIONS
Indexes on the relationship columns (safe to re-run).
POSTS_SCHEMA
posts table (the original spec schema) plus the unique post_id index.
PROFILES_SCHEMA
profiles table: one row per scraped nick, upserted every scrape.
RESEARCH_SCHEMA
Research projects and their items (see research). Items are unique per project, kind and ref; deleting a project deletes its items.
