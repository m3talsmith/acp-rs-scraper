Terminal UI (2.0): the default when no flags are given (or with --tui).

Browse every nick and post in the local database offline, open post details that cross-load linked posts, search in place, and drive scrape / export / import / maintenance from a menu bar built from the CLI flags. Anything that writes runs the headless CLI as a child process (jobs), so it can be cancelled, and keeps running in the background when you quit.

Layout: mod.rs (event loop), state (pure state + transitions), input (keys/mouse), layout (geometry), widgets (drawing), modals, commands (menu ↔ flags), data (read-only DB), jobs, theme (styles), theming (theme files in the app), editor (Shift-F5).

Modules§

commands
The menu bar’s command catalog and the menu → command-line bridge.
data
What the TUI reads: nicks, posts, attachments. SqliteStore opens the database read-only (every write goes through a headless job); MemStore is an in-memory stand-in for tests and headless renders.
editor
The theme editor (Shift-F5): full screen, the palette and every element on the left (swatch, value, * when changed, ⚠ below 3:1 contrast), a live preview on the right drawn by the real UI code over sample posts. Tab flips dark / light; colours come from a hex field or a grid (16 colours, the 216 cube, 24 greys, @ palette references). ^S saves, ^R reverts, ^N new, ^D duplicate, ^X delete, [ ] other themes, Esc closes (asking first when there are unsaved changes).
empty_anim
The animation in the empty Body: text frames played on a loop.
images
Pictures in the terminal: the header logo and post images.
input
Keyboard and mouse → state transitions (every action has both).
jobs
Background jobs: scans, exports, imports and maintenance run as the headless CLI in a child process (same binary, argv built by crate::tui::commands), in its own process group with output in ~/.acp/logs/tui-<kind>-<stamp>.log. Cancel kills it; quitting the TUI leaves it running (detached).
layout
Screen geometry (pure, so it is unit-tested): the base layout, the post list ↔ detail split (the “slide up”), and the nested detail stack (the “push the previous detail up”).
markdown
Post bodies as Markdown → styled, word-wrapped ratatui lines: headings, bold / italic / strikethrough, inline and block code, bullet and numbered lists, block quotes and links. Single line breaks are kept (bodies are stored as plain text whose newlines matter), and paragraphs stay separated by a blank line.
modals
Modals: floating over the layout (small margin, dimmed background), each closing with ModalResult::ClosedCancelled or ModalResult::ClosedSubmitted.
sample
Sample posts for the theme editor’s live preview (never the real database).
state
TUI state and its pure transitions (no terminal, no network): nick selection, the Body views (nick posts / search results), the detail stack, menu state, modals and the side effects the event loop must carry out.
theme
The single source of TUI styling. Colours come from a theme file (~/.acp/themes/<name>.toml, see crate::themes); without one every colour is the terminal’s own (Color::Reset) and the layout still works.
theming
Theme files inside the TUI: selecting, previewing, reloading and exporting themes, and the picker behind F5 and the header’s ‹theme› ▾ switch.
widgets
Drawing: every widget renders from App and records its clickable areas in App::hits (so mouse input hits exactly what was drawn).
